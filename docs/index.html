What's inside무엇이 담겼나

Four capabilities the plugins compose from.플러그인이 조합하는 네 가지 역량.

🔁

Loop-engineering harnesses루프 엔지니어링 하네스

MVP, feature-loop, and generic loops that iterate until a deterministic gate passes — a Stop-hook engine judges completion, with max-iteration / no-progress / time guardrails.결정론 게이트가 통과할 때까지 반복하는 MVP·feature-loop·generic 루프 — Stop훅 엔진이 완료를 판정하고, 최대 반복·no-progress·시간 가드레일이 폭주를 막습니다.

🤝

Multi-agent teams멀티 에이전트 팀

Maker/checker separation with adversarial verification — the checker has no Edit tool by design, so it can't quietly fix what it's meant to falsify. Six team patterns to compose from.적대적 검증을 갖춘 maker/checker 분리 — checker는 설계상 Edit 도구가 없어 반증 대상을 조용히 고칠 수 없습니다. 6가지 팀 패턴을 조합합니다.

🚦

Gated workflows게이트 워크플로우

Spec-driven development, TDD loops, code review, retrospectives, and release flows — each gated so scope drift and unverified work can't slip through.스펙 주도 개발, TDD 루프, 코드 리뷰, 회고, 릴리스 흐름 — 각각 게이트로 묶여 스코프 드리프트와 미검증 작업이 빠져나가지 못합니다.

🪝

Hook-driven verification훅 기반 검증

PreToolUse/Stop/SessionEnd hooks enforce the rules — guard against test deletion, unverified "passes", and silent hook mis-activation. Tested on an ubuntu + macOS bats matrix.PreToolUse/Stop/SessionEnd 훅이 규칙을 집행합니다 — 테스트 삭제, 미검증 "통과", 훅 조용한 미발화를 방어. ubuntu + macOS bats 매트릭스로 검증됩니다.

★ Featured대표 플러그인

observe — the self-measuring harnessobserve — 스스로를 계측하는 하네스

Every other plugin does work. observe watches the harness itself — which skills and agents actually fire, why, and whether they complete — and turns that into concrete improvements. 다른 플러그인이 일을 한다면, observe는 하네스 그 자체를 지켜봅니다 — 어떤 스킬·에이전트가 실제로, 왜 발화하고, 완주하는지 — 그리고 그것을 구체적 개선으로 바꿉니다.

Claude Code's native /usage shows cost and tokens. observe shows the layer above it — which skills and agents fire, why, whether they complete, and which go stale or uncorrected — the harness-health view cost metrics can't give you. Claude Code 네이티브 /usage가 비용·토큰을 본다면, observe는 그 위층을 봅니다 — 어떤 스킬·에이전트가 왜 발화하고, 완주하며, 어느 것이 정체·미교정되는가 — 비용 지표로는 얻을 수 없는 하네스 건강 관점입니다.

🧬 Inspired by HermesHermes에서 영감

Nous Research's Hermes Agent grows by autonomously creating skills from experience. observe borrows that self-improvement spirit — and ports the deterministic half of its curator: usage lifecycle (stale / archive candidates) and correction signals.Nous Research의 Hermes Agent는 경험에서 스킬을 자율 생성하며 성장합니다. observe는 그 자기개선 정신을 빌려오되, curator의 결정론 절반을 이식했습니다: 사용 라이프사이클(stale / archive 후보)과 교정 신호.

🔎 Evaluation-first평가 우선

Where Hermes generates, observe measures and proposes. It surfaces dead / stale assets, missed activations, and skills whose runs go uncorrected — then drafts the fix. You approve; it never edits a file silently.Hermes가 생성한다면, observe는 계측하고 제안합니다. 사장·정체 자산, 놓친 발화, 교정 없이 끝난 스킬 실행을 드러내고 수정안을 초안까지 만듭니다. 승인은 당신이 하며, 어떤 파일도 조용히 고치지 않습니다.

How to use it — three steps사용법 — 세 단계

Turn on tracing (opt-in — it records prompt text locally, so it's off by default):계측을 켭니다 (opt-in — 프롬프트 원문이 로컬에 기록되므로 기본은 꺼짐):

# shell profile, or settings.json "env"
export OBSERVE_TRACE=1

Work normally. Six hooks log every prompt → skill → agent → result → session boundary:평소대로 작업합니다. 6종 훅이 프롬프트 → 스킬 → 에이전트 → 결과 → 세션 경계를 기록합니다:

.claude/skill-trace.jsonl   # append-only, joined by session_id / prompt_id

Ask for the report — deterministic aggregation → LLM interpretation → proposals:리포트를 요청합니다 — 결정론 집계 → LLM 해석 → 개선 제안:

/observe-report
# unused & stale/archive candidates · missed activations
# correction signals · description-tuning drafts

"Completion is judged by the harness, not the model" — observe extends that to the harness's own health: measured, not assumed."완료 판정은 모델이 아니라 하네스가 한다" — observe는 그 원칙을 하네스 자신의 건강으로 확장합니다: 짐작이 아니라 계측으로.

Local observability — no SaaS로컬 관측 — SaaS 없음

There is no hosted service. Everything runs on your machine.호스팅 서비스는 없습니다. 전부 당신의 기기에서 돕니다.

observe's traces live in a local .jsonl file. For the cost/token side, the optional Grafana stack under infra/otel is a docker-compose you bring up yourself — it receives Claude Code's built-in OpenTelemetry (cost, tokens, events) and renders it next to your skill traces. Everything binds to loopback only; your prompts and metrics never leave your laptop. observe의 트레이스는 로컬 .jsonl 파일에 있습니다. 비용/토큰 쪽은 infra/otel의 Grafana 스택 — 직접 띄우는 docker-compose — 가 담당합니다. Claude Code 내장 OpenTelemetry(비용·토큰·이벤트)를 수신해 스킬 트레이스 옆에서 보여줍니다. 전부 루프백에만 바인딩되며, 프롬프트도 메트릭도 노트북을 떠나지 않습니다. 

# bring the local observability stack up
cd infra/otel
docker compose up -d
# Grafana → http://localhost:3000  (Claude Code cost/token dashboards, EN/KO)
Why docker-compose and not a SaaS? Trust in a harness comes from running it yourself, not from a dashboard you rent. The stack is here so you can verify locally — spin it up, watch the numbers, tear it down. Nothing is uploaded, nothing is sold. 왜 SaaS가 아니라 docker-compose인가? 하네스에 대한 신뢰는 빌린 대시보드가 아니라 직접 돌려보는 데서 옵니다. 이 스택은 로컬에서 직접 확인하라고 있는 것입니다 — 띄워서 숫자를 보고, 내리면 끝. 아무것도 업로드되지 않고, 아무것도 팔지 않습니다.

"Completion is judged by the harness, not by the model.""완료 판정은 모델이 아니라 하네스가 한다."

Deterministic gates — tests, linters, exit codes, marker files — decide when a loop stops. The model does the work; the harness certifies it's done. Every plugin here is built on that line.결정론 게이트 — 테스트·린터·종료코드·마커 파일 — 이 루프의 종료를 결정합니다. 모델은 작업을 하고, 하네스는 완료를 인증합니다. 여기 모든 플러그인이 이 원칙 위에 세워졌습니다.
