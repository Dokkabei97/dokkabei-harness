# 통제 매핑표 — git 네이티브 증적 → 심사 통제

eng-gov 산출물을 SOC2 Type II·ISMS-P·금융권 심사 통제에 매핑한다. `/gov-audit`가 이 표를 근거로 `audit-log.jsonl`과 게이트 결과를 **한국어 심사 증적 문서**로 변환한다(시장 차별화 포인트). 법 해석·인증 취득 판단은 legal 위임 — 이 표는 "어떤 산출물이 어떤 통제의 증거가 되는가"의 매핑일 뿐이다.

## 매핑표

| eng-gov 산출물 / 게이트 | SOC2 (2017 TSC) | ISMS-P (2023) | 증적 성격 |
|------------------------|-----------------|---------------|-----------|
| `evidence.json` + `gate-change-evidence` (변경 승인·4-eyes) | **CC8.1** 변경 관리 | **2.9.1** 변경관리 | 변경별 SHA·승인자·게이트 결과 |
| `gate-secrets` (신규 시크릿 차단) | CC6.1 논리적 접근 | **2.7** 암호화 / 2.8.x | 시크릿 노출 방지 기록 |
| `gate-supply-chain` (SBOM·CVE·라이선스) | CC7.1 취약점 관리 | **2.8** 정보시스템 도입·개발 보안 | SBOM·취약점 스캔 증적 |
| `gate-policy` (IaC 정책) | CC7.1 / CC8.1 | 2.8 / 2.10 시스템·서비스 운영 | 인프라 구성 정책 준수 |
| ADR + `gate-adr` (결정 이력) | CC2.2 내부 커뮤니케이션 | 2.1 정책·조직 | 아키텍처 결정 append-only 이력 |
| SLO·에러버짓 + `gate-error-budget` | A1.1 가용성 목표 | 2.10 운영관리 | 가용성 목표·버짓 판정 |
| 포스트모템 | CC7.3/CC7.4 사고 대응 | **2.11** 사고 예방·대응 | 블레임리스 사후분석·재발방지 액션 |
| `audit-log.jsonl` (append-only) | CC4.1 모니터링 | 2.9 시스템·서비스 운영 | 게이트 실행 감사 로그 |

## 핵심 증적 흐름

1. **변경통제(가장 중요)**: 커밋 → `/gov-change`가 위험 등급 + evidence.json → `gate-change-evidence`가 4-eyes·게이트 그린 검증 → SOC2 CC8.1 / ISMS-P 2.9.1의 결정론 증거.
2. **공급망**: `gate-secrets` + `gate-supply-chain` 실행 기록이 high 변경 evidence에 강제 포함 → ISMS-P 2.8.
3. **감사 추적**: `/gov-audit`가 `run-registered.sh` 결과를 `audit-log.jsonl`에 append + 한국어 문서로 변환 → 심사관 대응.

## 미확정·주의

- ISMS-P는 2026 대개편(예비심사·증적 중심)·2027.7 의무화가 진행 중 — 항목 번호는 심사 시점 기준으로 재확인(**갱신 필요** 스탬프).
- 이 매핑은 **인증 취득을 보장하지 않는다**. 통제의 "결정론 반쪽"(문서·게이트 존재)일 뿐, 운영 실효성 판단과 인증심사는 별개다.
- 금융권 책무구조도·전자금융감독규정 등 업권 특화 통제는 v2 백로그(수요 확인 후).
