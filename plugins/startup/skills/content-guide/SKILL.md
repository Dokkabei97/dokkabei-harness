# Content Guide — 콘텐츠 제작 가이드

콘텐츠의 톤 일관성은 세션 기억이 아니라 파일이 보장한다('상태는 파일에').
이 스킬은 그 기준 파일인 `brand-voice.md`의 스키마와, 유형별 콘텐츠 구조 템플릿을 정의한다.

## When to Apply
- `/content-draft`가 brand-voice.md를 물화(최초 인터뷰)하거나 참조해 초안을 쓸 때
- `growth-marketer`가 블로그·SNS·보도자료·이메일 콘텐츠를 작성·검수할 때
- 브랜드 보이스를 새로 정의하거나 갱신(`--revoice`)할 때
- 콘텐츠 초안의 브랜드·리스크 셀프 체크 기준이 필요할 때

## brand-voice.md — 물화 규칙과 스키마

### 물화 규칙
| 규칙 | 내용 |
|------|------|
| 위치 고정 | `.planning/business/brand-voice.md` — 모든 콘텐츠 생성이 이 경로를 Read |
| 인터뷰는 최초 1회 | 파일이 있으면 인터뷰 없이 참조만. 갱신은 `--revoice` 또는 직접 편집 |
| 기본값 승계 | `lean-canvas.md`(UVP·세그먼트), `market-research.md`(세그먼트·차별점)가 있으면 인터뷰 기본값으로 제안 |
| 근거 자산 공백 허용 | 근거 자산이 "없음"이면 그대로 기록 — 이후 초안에서 수치·사례 창작이 금지되고 `[근거 필요]` 표기가 강제된다 |

### 5문항 인터뷰 규격
| # | 질문 | 기록 섹션 |
|---|------|-----------|
| 1 | 어떤 문체·성격으로 말하는 브랜드인가? (해요체/합니다체 + 형용사 2~3개) | `## 톤` |
| 2 | 절대 쓰면 안 되는 단어·표현은? (과장·비방·내부 용어) | `## 금지 표현` |
| 3 | 주 독자는 누구이고 사전 지식 수준은? | `## 타깃 독자` |
| 4 | 모든 콘텐츠가 반복해야 할 핵심 메시지 1~3개는? | `## 핵심 메시지` |
| 5 | 주장을 뒷받침할 근거 자산은? (수치·고객 사례·수상·인증) | `## 근거 자산` |

### 파일 스키마
```markdown
# 브랜드 보이스: [제품/회사명]

## 톤
- 문체: 합니다체 (보도자료·이메일), 해요체 (SNS)
- 성격: 전문적이되 과장 없는, 개발자에게 솔직한

## 금지 표현
- "최고", "유일한", "혁신적인" (근거 없는 절대 표현)
- "간단하게", "쉽게" (독자의 난이도 경험을 단정)
- 경쟁사 실명 비방

## 타깃 독자
- 주 독자: [세그먼트 — 예: 5~50인 스타트업의 백엔드 개발자]
- 사전 지식: [예: 검색 인프라 운영 경험 있음, 마케팅 용어에는 낯섦]

## 핵심 메시지
1. [예: 검색 인프라 운영 시간을 주 10시간 → 1시간으로 줄인다]
2. [예: 설정 3줄로 시작한다]

## 근거 자산
| 자산 | 내용 | 출처/검증 |
|------|------|-----------|
| 베타 지표 | 파일럿 3개 팀 평균 운영 시간 87% 감소 | 내부 계측 (2026-05) |
| 고객 사례 | A사 도입 후기 인용 허락 확보 | 인터뷰 녹취 |
```

## 유형별 구조 템플릿 개요

상세 구조·분량·작성 팁·골격 예시는 references/에 위임한다. 초안 작성 전 해당 유형 파일을 읽는다.

| 유형 | 핵심 구조 (한 줄) | 상세 |
|------|-------------------|------|
| blog | 후킹 제목 → 문제 공감 리드 → 소제목 본문(근거) → CTA | [references/blog-template.md](references/blog-template.md) |
| sns | 첫 줄 훅 → 본문 1메시지 → CTA/해시태그 (플랫폼별 분량 상이) | [references/sns-template.md](references/sns-template.md) |
| pr | 역피라미드: 헤드라인 → 리드(5W1H) → 본문·인용문 → 보일러플레이트 | [references/pr-template.md](references/pr-template.md) |
| email | 제목줄+프리헤더 → 본문 1주제 → CTA 1개 + (광고성이면) 법정 표기 | [references/email-template.md](references/email-template.md) |

## 공통 품질 체크리스트

초안 완성 후 셀프 체크. 하나라도 실패하면 산출 전에 교정한다.

| # | 체크 | 판정 방법 |
|---|------|-----------|
| 1 | 금지 표현 잔존 0건 | brand-voice.md `## 금지 표현` 항목을 Grep |
| 2 | 무근거 수치·주장 0건 | `## 근거 자산`에 없는 수치는 `[근거 필요]` 표기 유지 |
| 3 | 핵심 메시지 1개 이상 포함 | `## 핵심 메시지`와 대조 |
| 4 | 톤·문체 일치 | `## 톤`의 문체 규칙과 대조 (유형별 예외는 톤 섹션에 명시된 대로) |
| 5 | 표시광고법 리스크 표현 점검 | 아래 리스크 표현 표 대조 → 감지 시 1줄 안내 |

## 표시광고법 리스크 표현 (감지용 요약)

감지 시 결과 보고에 1줄 안내만 남긴다:
`legal 플러그인 /compliance-check --regulation ecommerce 검토 권장`.
**적법/위법 판정은 이 스킬의 범위 밖**이다 — 문서 수준 협업 규약으로 안내까지만.

| 유형 | 리스크 표현 예 | 낮은 리스크 대안 |
|------|----------------|------------------|
| 절대적 표현 | 최고, 유일, 1위, 업계 최초 | 근거·조사기관·시점 병기 시에만 사용 |
| 보장성 표현 | 100% 보장, 무조건, 확실히 | 조건·범위를 명시한 서술 |
| 비교 단정 | OO보다 2배 빠름 (근거 없음) | 자체 벤치마크 조건 병기 또는 삭제 |
| 효능 단정 | 매출이 오릅니다, 반드시 개선 | 고객 사례 인용 ("A사는 ~했다") |
| 부당 유인 | 지금만, 곧 마감 (사실 아님) | 실제 기한·수량이 있을 때만 |

이메일의 광고성 정보 표기 의무((광고) 표기·수신거부 안내 등)는
[references/email-template.md](references/email-template.md) §법정 표기에서 다룬다.
