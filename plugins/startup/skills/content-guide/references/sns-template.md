# SNS 템플릿

플랫폼별 분량·문법이 크게 다르므로 `--platform`을 먼저 확정한다.
공통 원칙: **1 포스트 = 1 메시지**. brand-voice.md 핵심 메시지 중 1개만 싣는다.

## 공통 구조

```
1. 훅 (첫 1~2줄)  — 피드에서 잘리기 전에 멈추게 하는 문장 (아래 훅 공식)
2. 본문           — 메시지 1개 + 근거 1개 (수치·사례는 근거 자산에서만)
3. CTA            — 행동 1개 (링크·댓글 유도·팔로우 중 택1)
4. 해시태그        — 플랫폼 규칙에 따름
```

## 훅 공식

| 공식 | 예 |
|------|-----|
| 반직관 선언 | "재색인 자동화의 병목은 코드가 아니라 승인 절차였습니다" |
| 구체 수치 결과 | "주 10시간 → 1시간. 파일럿 3개 팀의 평균입니다" |
| 독자 상황 질문 | "금요일마다 재색인 당번을 정하고 있나요?" |
| 실패 고백 | "첫 설계에서 캐시를 완전히 잘못 잡았습니다" |

금지: 낚시 후 무관한 본문, 근거 없는 절대 표현(brand-voice.md 금지 표현 대조).

## 플랫폼별 규격

| 플랫폼 | 분량 권장 | 문체 힌트 | 해시태그 | 비고 |
|--------|-----------|-----------|----------|------|
| LinkedIn | 600~1,300자 | 합니다체, 전문적 | 0~3개 (말미) | 첫 2줄에서 접힘 — 훅 필수. 줄바꿈 잦게 |
| X | 280자 (스레드 시 트윗당 1주장) | 간결체 허용 | 0~2개 | 스레드는 1번 트윗이 훅+요약 |
| Instagram | 캡션 300~800자 | 해요체 친화 | 3~10개 (말미/첫 댓글) | 이미지/카드가 주인공 — 카드 문구도 함께 제안 |
| Threads | 500자 내 | 대화체 | 지양 | 질문형 마무리로 답글 유도 |

## 시리즈/스레드 규칙

- 긴 내용은 억지로 압축하지 말고 스레드(X)·카루셀(Instagram)로 분할
- 분할 단위: 1개 포스트/카드 = 1개 주장 또는 1개 단계
- 마지막 포스트에만 CTA 배치

## 골격 예시 (LinkedIn)

```markdown
재색인 자동화의 병목은 코드가 아니라 승인 절차였습니다.

파일럿 3개 팀을 계측해 보니, 실제 재색인 실행 시간은 주 1시간이 안 됐습니다.
나머지 9시간은 "언제 돌릴지 정하고, 승인받고, 지켜보는" 시간이었습니다.

그래서 우리는 실행이 아니라 판단을 자동화했습니다.
(근거: 내부 계측, 2026-05)

바뀐 것:
→ 재색인 판단: 임계치 기반 자동 제안
→ 승인: Slack 원클릭
→ 관찰: 완료/이상만 알림

같은 문제를 겪고 있다면, 설정 3줄로 시작할 수 있습니다. (댓글에 링크)

#검색인프라 #DevOps
```

## 골격 예시 (X 스레드)

```markdown
1/ 주 10시간 → 1시간. 파일럿 3개 팀의 검색 운영 시간 변화입니다.
   무엇을 자동화했는지 정리합니다. 🧵

2/ 병목은 재색인 '실행'이 아니라 '판단과 승인'이었습니다. (내부 계측 기준)

3/ 그래서 임계치 기반 자동 제안 + Slack 원클릭 승인으로 바꿨습니다.

4/ 설정 3줄로 시작할 수 있습니다 → [링크]
```
