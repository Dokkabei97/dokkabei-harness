# 블로그 템플릿

brand-voice.md의 톤·핵심 메시지를 전제로 한 구조 템플릿. 퍼널 단계(TOFU/MOFU/BOFU)에 따라
목적과 CTA가 달라진다 — 퍼널 전략 자체는 growth-hacking-guide 스킬 참조.

## 퍼널 단계별 목적

| 단계 | 목적 | 주제 예 | CTA |
|------|------|---------|-----|
| TOFU (인지) | 문제 인식·검색 유입 | "검색 인프라 운영이 힘든 5가지 이유" | 뉴스레터 구독, 관련 글 |
| MOFU (고려) | 해결 방법 비교·신뢰 구축 | "ES 운영 자동화 도구 비교", 기술 딥다이브 | 가이드 다운로드, 데모 |
| BOFU (전환) | 제품 선택 근거 제공 | 고객 사례, 마이그레이션 가이드 | 무료 체험, 도입 문의 |

## 구조

```
1. 제목        — 독자의 문제/이득 + 구체성 (숫자·대상 명시)
2. 리드 (2~4문장) — 독자의 상황 공감 → 이 글이 주는 것 예고
3. 본문        — 소제목(H2) 3~6개, 소제목만 읽어도 흐름이 잡히게
   - 주장마다 근거(brand-voice.md 근거 자산 또는 [근거 필요])
   - 코드/표/스크린샷 등 스캔 가능한 요소 1개 이상
4. 요약        — 핵심 3줄 (bullet)
5. CTA         — 퍼널 단계에 맞는 행동 1개
```

## 제목 공식

| 공식 | 예 |
|------|-----|
| 숫자 + 대상 + 이득 | "5인 팀이 검색 운영 시간을 87% 줄인 방법" |
| 문제 직격 질문 | "매주 10시간을 인덱스 재색인에 쓰고 있나요?" |
| How-to + 구체 조건 | "설정 3줄로 ES 모니터링 시작하기" |
| 실패담/교훈 | "우리가 검색 캐시를 잘못 설계하고 배운 것" |

금지: 낚시성 과장("충격", "미쳤다"), 근거 없는 절대 표현(brand-voice.md 금지 표현과 대조).

## SEO 기본

- 타깃 키워드 1개를 제목·첫 문단·H2 하나에 자연스럽게 포함 (밀도 강제 금지)
- 메타 설명 초안 1~2문장을 문서 하단에 별도 제공
- H1은 제목 1개만, 본문은 H2/H3 계층 유지
- 내부 링크 후보(기존 글·문서)를 `[내부 링크 후보]`로 표기

## 분량 가이드

| --length | 분량 | 용도 |
|----------|------|------|
| short | 600~900자 | 공지형, 릴리스 노트형 |
| standard | 1,500~2,500자 | 일반 블로그 (기본) |
| long | 3,000자+ | 기술 딥다이브, 비교 가이드 |

## 골격 예시

```markdown
# 5인 팀이 검색 운영 시간을 87% 줄인 방법

매주 금요일마다 인덱스 재색인에 반나절을 쓰고 있다면, 이 글은 그 시간을
어디서 되찾을 수 있는지 보여줍니다. 파일럿 3개 팀의 실제 계측 결과를 기준으로 정리했습니다.

## 어디서 시간이 새는가
[페인포인트 — 근거: 내부 계측 (2026-05)]

## 자동화할 수 있는 것과 없는 것
[본문 + 표]

## 도입 첫 주에 바뀐 것
[고객 사례 인용 — A사 인터뷰]

## 요약
- ...3줄

**지금 설정 3줄로 시작해 보세요 → [무료 체험]**

---
메타 설명: 5인 스타트업 팀이 검색 인프라 운영 시간을 주 10시간에서 1시간으로 줄인 과정과 계측 결과.
```
