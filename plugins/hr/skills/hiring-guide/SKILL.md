# 채용 실무 가이드 (Hiring Guide)

hr 하네스(recruiting-advisor·people-ops-advisor, `/jd-draft`·`/interview-kit`·`/onboarding-doc`)의 공통 실무 토대.
모든 산출물은 실무 구조 설계이며, 노동법 쟁점은 아래 에스컬레이션 규약에 따라 legal 플러그인에 위임한다.

## When to Apply
- JD·채용 공고를 작성하거나 차별 표현을 점검할 때
- 면접 질문·평가 루브릭·채용 퍼널을 설계할 때
- 온보딩 체크리스트·30-60-90 플랜·평가 제도를 만들 때
- HR 산출물에서 노동법 판단이 필요한 신호가 감지될 때 (→ 에스컬레이션 규약)

## 채용 퍼널 표준 구조

```
소싱 → 서류 → 면접(단계별 역량 분담) → 레퍼런스 체크 → 오퍼 → 온보딩
```

| 단계 | 측정 대상 | 원칙 |
|------|----------|------|
| 서류 | 필수 요건 충족 여부 | 필수/우대를 분리한 체크리스트로 판정 — 인상 평가 금지 |
| 면접 1 (직무) | 직무 역량·문제 해결 | 행동 질문(STAR) + 실무 과제, 역량별 루브릭 채점 |
| 면접 2 (협업/컬처) | 협업·커뮤니케이션·가치 정합 | 직무 면접과 측정 역량 중복 제거 |
| 레퍼런스 | 행동 패턴 교차 검증 | 후보자 동의 필수, 질문은 직무 관련으로 한정 |
| 오퍼 | — | 조건부 문구·처우 조항은 법률 접점(⚠ 표 참조) |

- 단계 수는 2~3개가 기본 — 단계 추가는 "새로 측정하는 역량"이 있을 때만
- 각 단계의 탈락 기준을 사전에 문서화 (사후 합리화 방지)

## JD 표준 구조

1. **제목**: 직무명 + 레벨 (내부 은어 금지)
2. **팀/미션**: 이 역할이 존재하는 이유 2~3문장
3. **핵심 책임**: 5±2개, 동사로 시작, 측정 가능한 결과 중심
4. **필수 요건**: 없으면 업무 불가능한 것만 — 3~5개 초과 시 재검토
5. **우대 요건**: 있으면 램프업이 빨라지는 것
6. **채용 절차**: 단계·예상 소요 기간 공개
7. **성장 제안**: 이 역할에서 얻는 경험·성장 경로

### 차별 표현 셀프 체크 (휴리스틱)

| 신호 | 예시 | 대체 방향 |
|------|------|----------|
| 연령 | "○세 이하", "젊은 조직에 어울리는" | 연령 표현 삭제, 역량 요건으로 대체 |
| 성별 | "○○ 업무에 적합한 여성", 성별 지정 | 직무 요건만 기술 |
| 용모·신체 | "용모 단정", 키·체중 조건 | 직무 수행과 무관하면 삭제 |
| 출신·학벌 | 특정 지역·학교 우대 | 역량·경험 기준으로 대체 |
| 혼인·임신 | "미혼자", 출산 계획 언급 | 전면 삭제 |

이 표는 탐지용 휴리스틱이다. **위법 여부 확정은 아래 규약에 따라 legal에 위임한다** — 채용 차별은 남녀고용평등법·고령자고용법 등에서 형사처벌·과태료 대상이 될 수 있는 영역이다.

## 역량 기반 면접 설계

- **역량 모델**: JD의 핵심 책임에서 4~6개 도출, 각 역량에 필수 근거 1줄
- **행동 질문(STAR)**: "~했던 경험을 말해달라" → Situation/Task/Action/Result를 후속 질문으로 유도. 가정형("~라면 어떻게 하겠나")보다 과거 행동 우선
- **후속 심화**: "본인 기여는 구체적으로 무엇이었나", "결과를 어떻게 측정했나", "다시 한다면 무엇을 바꾸겠나"
- **금지 질문**: 혼인·임신·출산 계획, 가족 배경·재산, 나이, 출신지, 종교·정치 성향 — 직무 무관 개인사는 차별 리스크

### 앵커 루브릭 (4단계)

| 단계 | 앵커 기준 |
|------|----------|
| 4 탁월 | 요구 수준을 넘는 구체 사례 + 본인 기여·측정 결과가 명확 |
| 3 충족 | 직무 요구 수준의 사례를 본인 행동 중심으로 제시 |
| 2 미달 | 사례가 피상적이거나 팀 성과에 묻어감 (본인 기여 불명확) |
| 1 부족 | 관련 사례 없음 또는 답변이 질문과 불일치 |

- 각 단계는 관찰 가능한 행동으로 기술 — "태도가 좋음" 같은 인상 항목 금지
- 종합 판정 규칙 사전 합의 (예: 필수 역량 2점 미만 1개면 불합격)
- 점수 근거는 답변 인용으로 기록 — 캘리브레이션과 이의 대응의 기초

## 온보딩 30-60-90 표준

| 시점 | 테마 | 완료 기준 예시 |
|------|------|---------------|
| 입사 전(D-7) | 준비 | 계정·장비·첫 주 일정 확정, 담당자 지정 |
| 첫 주 | 정착 | 도구·도메인 투어, 1:1 완료, 첫 소과제 배정 |
| 30일 | 학습 | 시스템/도메인 이해, 첫 기여(작은 결과물) 완료 |
| 60일 | 기여 | 독립 과제 수행, 팀 프로세스 내 역할 확립 |
| 90일 | 자립 | 자기 영역 오너십, 개선 제안 1건 이상 |

- 모든 마일스톤에 **측정 가능한 완료 기준**과 매니저 체크인 어젠다를 부여
- 체크리스트 항목마다 담당자(입사자/매니저/피플팀) 지정
- 수습 평가와 연계되는 순간 법률 접점이 된다 (⚠ 표 참조)

## ⚠ 법률 판단 필요 트리거 표

아래 트리거가 감지되면 **legal:labor-ip-counsel 호출이 강제된다**. HR 하네스는 이 표의 쟁점에 대해 확정 판단을 출력할 수 없다.

| 트리거 | 감지 신호 예시 | 관련 법령 | 조치 |
|--------|---------------|----------|------|
| 채용 차별 금지 | 공고·전형 기준의 연령/성별/출신 조건, 면접 금지 질문 사용 | 남녀고용평등법, 고령자고용법, 채용절차법 | legal:labor-ip-counsel 위임 |
| 해고·권고사직 | 저성과 조치, 수습 해지(본채용 거부), 계약 갱신 거절 | 근로기준법 §23·§26·§27 | legal:labor-ip-counsel 위임 |
| 취업규칙 | 제·개정, 불이익 변경, 인사 규정 신설 | 근로기준법 §93·§94 | legal:labor-ip-counsel 위임 |
| 연차·수당·임금 | 연차 부여 기준, 연장/야간/휴일수당, 포괄임금, 임금 체불 | 근로기준법 §56·§60·§109 | legal:labor-ip-counsel 위임 |
| 근로계약 조항 | 계약서 필수기재, 위약금·경업금지, 조건부 오퍼 문구 | 근로기준법 §17·§20 | legal:labor-ip-counsel 위임 |
| 고용 형태 구분 | 프리랜서/도급/파견 활용, 위장도급 의심 | 근로기준법, 파견법 | legal:labor-ip-counsel 위임 |
| 직장 내 괴롭힘·안전 | 괴롭힘 신고 처리, 조사 절차 | 근로기준법 §76의2·3 | legal:labor-ip-counsel 위임 |
| 조직 규모 경계 | 5인 미만↔이상 전환 (적용 법령 변경) | 근로기준법 §11 | legal:labor-ip-counsel 위임 |

## 도메인 플러그인 간 리스크 에스컬레이션 규약

hr(실무) → legal(법률 판단) 위임의 표준 절차. 다른 도메인 플러그인 쌍에도 동일 패턴을 적용한다.

1. **감지**: HR 작업 중 위 트리거 표의 신호가 나타나면 즉시 플래그 — "아마 괜찮음" 같은 자체 완화 금지
2. **표시**: HR 산출물의 해당 위치에 `⚠ 법률 판단 필요` 표시 + 사실관계 요약(조직 규모, 당사자 지위, 쟁점 문구 원문)을 함께 기록
3. **위임**: Task 도구로 `legal:labor-ip-counsel` 호출 (legal 플러그인 미설치/미가용 시 사용자에게 legal 하네스 실행을 명시적으로 안내하고 해당 항목을 미결로 남김)
4. **반영**: legal 회신을 근거로 산출물을 수정하되, 법령 해석을 HR 문서에서 재가공·요약 변형하지 않고 원문 인용
5. **한계 고지**: 최종 산출물에 "법률 쟁점은 legal:labor-ip-counsel 1차 진단 기반이며 노무사·변호사 자문을 대체하지 않음"을 명시

역방향(legal → hr)은 이 규약의 대상이 아니다 — legal이 실무 서식이 필요하면 hr 커맨드를 참조 안내만 한다.
