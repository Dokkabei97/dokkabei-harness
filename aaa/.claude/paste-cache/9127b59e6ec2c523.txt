✅ 꼭 챙겨야 할 것 (Must-Dos)
1. 명확하고 구체적인 설명 (Description) 작성

핵심: skill.md 파일의 상단(Frontmatter)에 있는 description은 AI가 이 스킬을 언제 사용할지 결정하는 가장 중요한 기준입니다 .

방법: 단순히 기능을 나열하기보다 "이 스킬을 언제 사용해야 하는지" 구체적인 상황을 명시하세요 . AI가 정확한 판단을 내릴 수 있도록 이 부분에 공을 들여야 합니다 .

2. 하나의 스킬은 하나의 워크플로우에 집중

핵심: 모든 것을 다 하려는 거대한 스킬보다는 특정 작업에 집중된 스킬이 더 좋습니다 .

이점: 작고 집중된 스킬 여러 개를 구성(Compose)하여 사용하는 것이 훨씬 효율적이며 , AI가 자동으로 여러 스킬을 조합해 사용할 수 있습니다 .

3. 단계적 공개 (Progressive Disclosure) 구조 준수

핵심: 컨텍스트 윈도우(토큰)를 아끼기 위해 정보를 단계적으로 구성하세요.

구조: 필수 메타데이터(Level 1) → 스킬 본문(Level 2) → 외부 참조 파일(Level 3) 순서로 구성하여, AI가 필요할 때만 깊은 정보를 읽도록 설계해야 합니다 .

4. 예시(Examples) 포함하기

핵심: AI가 성공적인 결과물이 무엇인지 이해할 수 있도록 입력과 출력의 예시를 포함하세요 . 예시가 있으면 AI가 지침을 따르기 훨씬 수월해집니다 .

5. 스킬 정의는 영어로 작성 (권장)

핵심: 한국어 사용자라도 스킬의 이름, 설명, 내부 지침은 영어로 작성하는 것이 좋습니다.

이유: 영어가 AI가 이해하기 더 명확하며, 토큰 소모량도 적기 때문입니다 .

6. '스킬을 관리하는 스킬' 도입 (고급)

핵심: 프로젝트가 커지면 스킬이 많아져 관리가 어려워집니다. Manage Skills 같은 관리용 스킬을 만들어, 새로운 규칙이나 패턴이 생길 때마다 스킬을 자동으로 업데이트하고 검증하도록 자동화하세요 .

❌ 피해야 할 것 (Must-Avoids)
1. 모든 정보를 skill.md에 덤핑(Dumping)하기

위험: 귀찮다고 모든 정보를 메인 파일에 때려 넣으면 안 됩니다 .

제약: 마크다운 본문(Body)은 5,000 토큰 이하로 유지해야 합니다 . 방대한 정보는 반드시 별도 파일로 분리하여 참조(Reference) 형태로 만드세요 .

2. 민감한 정보 하드코딩

위험: API 키나 비밀번호 같은 민감한 정보를 skill.md나 스크립트 파일에 직접 적지 마세요 . 보안상 매우 위험합니다.

3. 런타임 패키지 설치 의존

제약: API 기반 스킬을 사용할 때는 실행 중에 추가 패키지를 설치할 수 없습니다 . 필요한 의존성(Dependencies)은 미리 컨테이너에 설치되어 있어야 합니다.

4. 모호한 설명 (Vague Description)

위험: 설명이 불명확하면 AI가 해당 스킬을 언제 꺼내 써야 할지 모릅니다 . AI가 스킬을 무시하거나 엉뚱한 상황에 실행하지 않도록 설명을 구체화하세요.
