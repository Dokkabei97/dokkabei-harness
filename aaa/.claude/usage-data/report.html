Getting started: Pipe your kubectl logs or docker-compose output into Claude Code's Bash tool and instruct it to iterate: read logs → hypothesize → fix → rebuild → re-check logs until the error disappears.
Paste into Claude Code:
I have a failing service. Here's how to debug it autonomously: 1. Run `kubectl logs -f deployment/[SERVICE] --tail=100` (or the equivalent docker/local command I'll provide) and capture the latest error. 2. Analyze the error—check the relevant source files, configs (YAML, Helm values, application.yml), and recent git changes. 3. Propose a root cause hypothesis and apply the minimal fix. 4. Rebuild/redeploy using `[BUILD COMMAND]` and re-check the logs. 5. If the error persists or a new one appears, repeat from step 1. Do NOT stop until the service starts cleanly or you've exhausted 5 iterations. 6. After success, commit the fix with a descriptive message and write a brief post-mortem summary. The service is [SERVICE NAME] and the current error is: [PASTE ERROR OR SAY 'check the logs'].
