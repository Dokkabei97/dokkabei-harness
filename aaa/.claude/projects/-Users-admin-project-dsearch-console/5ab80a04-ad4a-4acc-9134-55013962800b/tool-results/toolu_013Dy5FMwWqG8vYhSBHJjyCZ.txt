     5→## Project Overview
     6→
     7→DSearch Console is a React-based web console for managing Elasticsearch clusters. It provides a UI for the DSearch Server APIs, enabling users to manage indices, collections, dictionaries, pipelines, and cluster settings.
     8→
     9→## Development Commands
    10→
    11→```bash
    12→# Install dependencies
    13→npm install
    14→
    15→# Start development server
    16→npm start
    17→
    18→# Build for production
    19→npm run build
    20→
    21→# Run tests
    22→npm test
    23→```
    24→
    25→**Note:** Node.js v10.20.1 is used in CI. The project uses `react-app-rewired` instead of standard `react-scripts`.
    26→
    27→## Architecture
    28→
    29→### Tech Stack
    30→- **React 16** with **Redux** for state management
    31→- **Material-UI 4.x** for component library
    32→- **styled-components** for CSS-in-JS styling
    33→- **react-router-dom 5.x** for routing
    34→- **axios** for HTTP requests
    35→- **react-app-rewired** with **customize-cra** for webpack configuration
    36→
    37→### Project Structure
    38→
    39→```
    40→src/
    41→├── Client.js          # Centralized API client with auth/session handling
    42→├── redux/
    43→│   ├── actions/       # Redux action creators (async thunks)
    44→│   ├── reducers/      # Redux reducers with initState pattern
    45→│   ├── constants.js   # Action type constants
    46→│   └── store/         # Redux store configuration
    47→├── routes/
    48→│   └── index.js       # Route definitions (dashboard, intro, auth)
    49→├── layouts/           # Page layout wrappers (Dashboard, Main, Auth)
    50→├── pages/             # Feature pages organized by domain
    51→├── theme/             # MUI theme with 6 color variants
    52→└── components/        # Reusable UI components
    53→```
    54→
    55→### Key Patterns
    56→
    57→**API Client (`src/Client.js`)**
    58→- Singleton class wrapping axios for all API calls
    59→- Automatic token refresh via `x-bearer-token` header
    60→- Cluster ID extracted from URL path and sent as `cluster-id` header
    61→- Session/localStorage for server URL (`SET_DSEARCH_SERVER`) and auth (`SET_DSEARCH_AUTH_USER`)
    62→
    63→**Redux Pattern**
    64→- Actions use `redux-thunk` for async operations
    65→- Action creators call `client.call({uri, method, data})` and dispatch results
    66→- Action types defined in `src/redux/constants.js`
    67→- Reducers use `initState` object with switch-case pattern
    68→
    69→**Route Structure**
    70→Three route groups with different layouts:
    71→- `dashboard`: Cluster management routes (`/{clusterId}/...`) → `DashboardLayout`
    72→- `intro`: Pre-cluster routes (`/cluster`, `/user`, `/role`) → `MainLayout`
    73→- `auth`: Login route (`/`) → `AuthLayout`
    74→
    75→**Component Styling Pattern**
    76→Extend MUI components with styled-components:
    77→```javascript
    78→import { Card as MuiCard } from "@material-ui/core";
    79→import { spacing, sizing } from "@material-ui/system";
    80→const Card = styled(MuiCard)(spacing, sizing);
    81→```
    82→
    83→**Async Component Loading**
    84→- `src/components/Async.js` provides lazy loading with configurable delay
    85→- Usage: `async(() => import("../pages/feature"), { time: 500 })`
    86→
    87→**Theme System**
    88→- 6 variants: Dark, Light, Blue, Green, Indigo, Teal (`src/theme/variants.js`)
    89→- Theme selected per cluster, stored in `authUser.cluster.theme`
    90→- Accessed via `maTheme[authUser.cluster.theme]`
    91→
    92→### Path Aliases (config-overrides.js)
    93→```javascript
    94→'~': './src'
    95→'@actions': './src/redux/actions'
    96→```
    97→
    98→## API Conventions
    99→
   100→All API calls go through the `Client` class:
   101→```javascript
   102→const client = new Client()
   103→client.call({
   104→  uri: '/elasticsearch/_cat/indices',  // DSearch server endpoint
   105→  method: 'GET',                       // HTTP method
   106→  params: { format: 'json' },          // Query params
   107→  data: { ... }                        // Request body
   108→})
   109→```
   110→
   111→The `uri` is relative to the DSearch server URL stored in session/localStorage.
   112→
   113→## Deployment
   114→

   116→- Production build served via nginx with SPA fallback (`try_files $uri $uri/ /index.html`)
   117→- Image pushed to `ghcr.io` container registry
