## 5) 잠재적 리스크/주의사항

- **호환성 리스크 (높음)**: `handler`, `rest-api` 패키지/모듈 리네이밍으로 외부 모듈/테스트/배포 스크립트의 import 경로가 깨질 수 있음.
- **쿼리 동작 리스크 (높음)**: `BaseQuery.keyword`/`channel` nullable화로 이전에 필수였던 값이 빠져도 동작 가능한 경로가 생김. `channel == null` 시 레이어별 기본 처리 로직이 누락되면 필터 누락/권한 누락 가능.
- **데이터 정합성 리스크 (중간~높음)**: `LegacyReserveSyncApplicationService#getDependencyId()`가 `afterData` 기준으로만 카테고리/몰 ID를 수집하면 `beforeData` 기반의 변동(삭제/이동 케이스)에서 의존 조회 누락 가능성.
- **인프라 의존성 리스크 (중간)**: Valkey bean 사용 모듈에서 `infrastructure.valkey` 스캔을 누락하면 `ValkeyTemplate`/`ValkeyConfig` 바인딩 실패.
- **스키마 동기화 리스크 (중간)**: `domain/cdc`에서 스키마 다운로드 자동화를 기본 빌드에서 분리한 뒤 `schemaSync` 실행 누락 시 코드생성 싱크 어긋날 수 있음.
- **운영 리스크 (중간)**: `application-outbound.yml`에서 기존 더미 stub 제거 후 환경별 프로퍼티 미제공 시 바인딩 실패 가능.
- **토픽/브로드캐스트 리스크 (중간)**: `dynamic-indexer-admin` 브로드캐스트 토픽 변경/미설정 시 동적 인덱싱 제어 메시지 미수신이 생길 수 있음.
