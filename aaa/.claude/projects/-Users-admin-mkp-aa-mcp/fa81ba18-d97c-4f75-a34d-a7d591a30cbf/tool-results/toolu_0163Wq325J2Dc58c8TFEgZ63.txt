Short answer:

- For reliable non-interactive spawned execution, add:
  - `--silent`
  - `--no-ask-user`
  - `--no-custom-instructions`
  - `--disable-builtin-mcps`
- The `--allow-all-tools` flag is usually okay, but it increases variability; keep it only if you actually need it.

I’ve patched it so Copilot is built with:

- `src/agents/copilot-agent.ts` now includes:
  - `--silent`
  - `--no-ask-user`
  - `--no-custom-instructions`
  - `--disable-builtin-mcps`

About stdin/stdout spawning:
- `stdio: ['pipe','pipe','pipe']` alone is not the direct cause of autonomy loops, but it does make the child non-interactive (`stdin` is not a TTY), which can push Copilot toward autonomous behavior.
- Better is to only use a writable stdin pipe when you really send context; otherwise use `ignore` for stdin.
- I updated executor flow to use conditional stdio in `src/orchestrator/executor.ts`:
  - `stdin: undefined -> ['ignore','pipe','pipe']`
  - `stdin: defined -> ['pipe','pipe','pipe']`
  - write stdin via `child.stdin.end(stdin)` when present.

Net effect:
- prevents accidental interactive-mode assumptions from pipe-only stdin,
- suppresses status chatter from script runs,
- disables question/clarification loops,
- reduces built-in MCP/tool variability.

I also ran `npm run -s build` after the changes.
