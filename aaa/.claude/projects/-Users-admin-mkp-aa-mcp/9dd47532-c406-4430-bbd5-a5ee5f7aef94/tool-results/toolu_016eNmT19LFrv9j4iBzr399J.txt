좋은 포인트 3개를 모두 짚으셨어요. 결론부터 정리하면:

1) 맞습니다. 현재 구현은 `analysisLevel`이 항상 존재합니다.  
- `src/agents/codex-agent.ts`에서 `analysisLevel` 계산은 `options.analysisLevel ?? this.config.defaultAnalysisLevel ?? "medium"`라서, 항상 `"low|medium|high|xhigh"` 또는 `"medium"`이 됩니다.  
- 따라서 `...(analysisLevel ? [analysisLevel] : [])`는 사실상 항상 추가됩니다.

2) `reasoning effort`는 현재 `codex exec` CLI 플래그로 직접 들어가지 않습니다.  
- 사용자가 준 `codex exec --help`(Usage 기준)에는 `low/medium/high/xhigh` 같은 별도 옵션이 없습니다.  
- 따라서 `["...","xhigh",...]` 같은 값은 플래그가 아니면 위치 인자로 해석됩니다.  
- 현재 환경에서는 `model_reasoning_effort`를 설정을 통해 주는 방식이 맞습니다. 즉:
  - 권장: `-c model_reasoning_effort=xhigh` (가능한 CLI라면)
  - 또는 `~/.codex/config.toml`의 `model_reasoning_effort = "xhigh"` (전역/프로필 기준)

3) 올바른 호출 패턴은 `OPTIONS` 먼저, 그 다음 `[PROMPT]`입니다.  
- `codex exec [OPTIONS] [PROMPT] [COMMAND]`
- stdin 사용 시: `-`를 PROMPT 위치에 둡니다.

현재 코드가 바르게 동작하려면 `analysisLevel`은 플래그 없이 값만 넣지 말고, 설정 오버라이드로 넣어야 합니다.

const args = [

  "--model", model,
  "--config", `model_reasoning_effort=${analysisLevel}`,
  "--sandbox", "read-only",
  "--output-last-message", outputFile,
  "-",
